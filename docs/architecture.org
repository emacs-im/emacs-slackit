#+title: Slackit
#+options: toc:2 num:nil

Slackit is an Appkit-based Slack client for Emacs.  It is a new implementation,
not a fork or compatibility layer for =emacs-slack=.  The package, feature,
files, commands, variables, and faces use the =slackit-= namespace so both
clients can be installed and loaded in one Emacs session.

Contract tests use isolated canonical Apps and Generated Surfaces with synthetic
credentials and transports.  Live-workspace authentication and transport checks
require deliberate account access outside those fixtures.

* Product boundary

Slackit owns Slack account configuration, protocol state, transport, error
semantics, event reduction, message rendering, and Slack-specific actions.
Appkit owns App/Surface lifecycle, serialized transitions and closed commands,
Generated Renderer transactions, stable-key reconciliation, semantic position,
composer geometry, continuous history-window mechanics, directories, and media
presentation.

The existing workspace projects have distinct roles:

- =emacs-slack= is the behavioral and Slack Web API/Web/Desktop realtime
  reference.  Slackit may port endpoint semantics and payload knowledge, but
  never loads its =slack-= modules or shares their global state, EIEIO models,
  LUI buffers, request worker, or symbols.
- =disco.el= is a room/gateway/Appkit reference: canonical state is committed
  before explicit Surface projection requests, and timelines use stable server
  keys.
- =emacs-qq= is the account-lifecycle reference: each stable account owns a
  separate Appkit application and state partition.
- =slk= is an independent Slack protocol and interaction reference.  Slackit
  reuses its measured room/reply pagination directions, stable
  conversation/timestamp action routing, emoji-name semantics, and lazy media
  UX; it does not copy slk's Go/TUI state machine, global caches, cross-workspace
  media credential fallback, optimistic reaction rollback, or redirect policy.
- =appkit.el/docs/integrator.org= is authoritative for reusable UI and update
  mechanics.  Slackit does not add a second projection, composer, history, or
  lifecycle framework beside it.

The compatibility floor is Emacs 32.0 with Appkit 0.3.0, =browser-session=,
=transient=, =plz=, and =websocket=.  Evil is an optional development/runtime
integration discovered after load.  No =request=, =circe=/LUI, =dash=, =s=, or
EIEIO dependency is required.

* Account identity and credentials

One registered Slack account owns one =slackit-account= Appkit application.
=ACCOUNT-ID= is required, local, stable, and chosen by the user.  It identifies
the Appkit application and appears in buffer names.  Slack team/self IDs are
protocol facts, not Appkit lifecycle IDs.  Browser-imported credentials pin
them; =auth.test= must agree with that identity, or bind a missing session-only
identity, before canonical state or realtime startup can proceed.

The default interactive entry point is:

#+begin_src emacs-lisp
(slackit-login "work")
#+end_src

Slackit uses the required =browser-session= package to open an account-isolated
login profile at =https://my.slack.com/customize=.  That page exposes the
=TS.boot_data= contract consumed by =slackit-session.js=; the
=https://app.slack.com/= landing page may authenticate successfully without
exposing the token and therefore must not be the capture target.
=browser-session= owns browser discovery, CDP/BiDi, isolated profile lifecycle,
cookie capture, and the private versioned capture file.  Slackit owns the
explicit =d=/=d-s=/=lc= allowlist, provider page script, Slack
origin/domain/value validation, and mapping to its own credential schema.
Provider logic never enters =browser-session=.

The provider page script returns nil until =TS.boot_data.api_token= exposes an
=xoxc-= token; when Slack exposes team/user IDs, the script records those too.
Cookie values and the page result exist only in the private capture file.
=browser-session= callbacks receive non-secret metadata.

After capture, Slackit explicitly reads the file, requires the configured
source URL, exactly one secure root-path cookie of each allowed name from a
=slack.com= domain, a valid =xoxc-= token, and compatible previously established
team/user identities.  It atomically writes a schema-versioned per-account auth
file with mode =0600= beneath =slackit-auth-directory=, then deletes the capture
file.  Per-account browser profiles remain available for later reauthentication;
clearing Slackit auth does not silently sign the browser out.

=M-x slackit= starts browser login when the selected account lacks private auth.
=M-x slackit-register-account= remains a session-only headless fallback, and
=slackit-credential-function= remains replaceable for deliberate auth-source or
automation integrations.  Manual token/cookie input is not the recommended
desktop workflow.

Credentials are an account-local bundle, never global URL-library state.
Tokens, cookies, realtime WebSocket URLs, capture contents, and response bodies
are never used in Appkit IDs, view IDs, state keys, buffer names, errors, or logs.
Diagnostics redact headers, URL queries/fragments, request/response bodies, and
WebSocket URLs before formatting them.

The credential router is origin- and endpoint-class-aware.  Fixed Web API
requests to =https://slack.com/api/= receive the account bearer token and
=xoxc= cookie bundle.  The browser-session realtime gateway is a separate exact
endpoint class: only =wss://wss-primary.slack.com/= receives the percent-encoded
=xoxc= query token, one =d= cookie, the captured browser =start_args=/
=agent_version= fingerprint, and the small WebSocket header set.  URL-library
global cookies are dynamically suppressed during its handshake so accounts
cannot contribute duplicate/cross-account Cookie headers.  Redirects, media
URLs, and presigned upload URLs never inherit Slack credentials.

Authenticated credentials build the Slack Web/Desktop gateway URL directly,
matching the measured =slk= client.  There is no legacy =rtm.connect= capability
fallback: session-only credentials first bind their workspace/user identity
through =auth.test=.  Only the exact gateway host is accepted, and receipt of
=hello= establishes readiness.  The secret gateway URL is never logged.
Hello/heartbeat/pong timeout, bounded reconnect backoff, and one pending
reconnect attempt per live generation remain generation-owned.  Reconnects
rebuild the authenticated gateway URL rather than adopting an event-provided
capability URL.

Only idempotent reads may honor server =Retry-After= automatically, with a
bounded account/view-owned delay.  =chat.postMessage= and every other write are
sent once; timeout or an unknown outcome is surfaced without automatic retry.
OAuth, token refresh, Socket Mode, and enterprise-token selection remain
outside the first slice.  Socket Mode transports scoped Slack App events and
cannot replace a logged-in user's Web/Desktop realtime stream.

* Ownership model

** Canonical account App

Each local account starts the stable =slackit-runtime--app-type= with
=:identity= and =:input=.  Its sole =slackit-runtime-model= aggregates the
canonical =slackit-account-state=, credential-bearing =slackit-transport=,
operation fences, desired realtime state, and exact App back-reference.
Public Slackit state/transport accessors read that model; no buffer creates a
surrogate App or a second authoritative account state.

Initial construction does not start transport.  The returned App is linked
before explicit bootstrap/connect transitions request finite Effects or a
Source.  Bootstrap observes identity and every conversation page, commits those
facts, and enables the realtime Source only after authenticated identity agrees
with the pinned credential.  Unknown senders and directory users use deduplicated
finite user Effects.  The emoji catalog is a separate finite Effect.

The realtime Source owns the existing WebSocket, hello timeout, heartbeat/pong
timers, and reconnect sequence.  Its cancellation capability closes actual
transport resources.  Source events enter App updates; transport callbacks do
not synchronously post into an active Appkit pass.  Account-lifecycle generations
fence HTTP/operations independently from connection-attempt generations, so a
socket reconnect cannot retire an unrelated write or history page.

Stopping revokes both generations before =appkit-app-close=.  Appkit cancels
Sources, Effects, HTTP and Surface handles.  Shutdown clears credential
references, operation fences, and account media specifications, and removes the
registry entry only if it still points to that exact App.  Matching a reused
account ID is never enough to authorize a late callback.

** Generated Surfaces

Stable Surface types preserve each derived major mode and pair the exact App
with a secret-free protocol identity:

- root: =(root)=
- conversation: =(room CONVERSATION-ID)=
- thread: =(thread CONVERSATION-ID ROOT-TS)=
- user: =(user USER-ID)=

Surface initialization captures its exact closed-command route.  Native
Generated Renderers reconcile directory/profile content or the chat timeline;
Surface updates apply controller consequences and return explicit
=appkit-projection-change= requests.  Account publication sends one routed
change batch per interested Surface, not an observer bridge or an invalidation
registry.  Modes run before attachment, and lifecycle-owned HTTP, profile
cleanup, and geometry setup run only after opening returns a ready Surface.

History cursors and exact windows belong to the room/thread Surface.  HTTP
receives that real Surface as =:owner=.  The Appkit history operation is only a
cancellation fence and binds the actual =slackit-http-request-handle=.  Responses
check the captured Surface, App, model state, route identity, account generation,
and operation before changing history.  Reads never fabricate acknowledgements.

Account writes can settle after their initiating room closes.  Composer
settlement separately checks the captured draft revision and auxiliary state.
Navigation-only =conversations.open= is owned by its initiating profile Surface;
retired navigation cannot create an IM or jump buffers.  Stopping a Surface
revokes authority but preserves its buffer and editable draft.

Reopening looks up only a package-owned host with matching stable account and
Surface identity, compatible derived mode, and no live attachment.  Names alone
never authorize buffer reuse.  The prior derived mode is invoked before the
new attachment; structured draft properties, auxiliary context, and input
history are restored through the chatbuf APIs.  The old Surface and its
callback route remain revoked even when the same buffer hosts a replacement
account App.

* Canonical state

=slackit-account-state= contains protocol facts, not rendered strings:

- connection/team/self metadata with explicit unknown/loading/error states;
- users keyed by exact Slack user ID;
- conversations keyed by exact conversation ID plus a stable visible order;
- explicit-knownness read facts such as =last_read=, never fabricated zeroes;
- messages partitioned by conversation ID and keyed by exact =ts=;
- separate top-level and =(conversation-id . root-ts)= reply indexes;
- normalized text references, thread metadata, reactions, and safe file
  summaries retained on canonical messages;
- sorted message-key sequences for projection;
- a monotonic mutation revision and per-message revisions/tombstones;
- the latest raw protocol facts required to normalize later events.

=slackit-decode-json= establishes the sole wire-shape boundary: JSON objects
become symbol-key alists and every JSON array becomes a proper list.  Entity
decoders and views consume that invariant directly; they do not accept or adapt
alternate sequence representations.  Unknown fields may be preserved there;
views never depend directly on raw HTTP or WebSocket envelopes.  Nested
=message_changed=, =message_deleted=, =message_replied=, ordinary reply, and
=thread_broadcast= envelopes are classified before reduction.  An ordinary
reply never becomes an accidental
top-level row; a broadcast reply appears once in the room and once in its
thread projection.

Slack IDs and timestamps are opaque strings.  Message identity is
=(CONVERSATION-ID . TS)=.  Within one room or thread the Appkit timeline row key
is =TS=.  Timestamp order uses =string<=; identity and ordering never convert
=ts= to an Emacs number.  Rendering may parse the integer seconds component
only to show a clock time.

History responses capture the account mutation revision at dispatch.  When a
page settles, its messages are merged only if a newer realtime mutation has
not changed or deleted the same key.  A delayed room or reply page therefore
cannot resurrect a deleted message or overwrite a newer edit.  HTTP responses,
realtime events, and action refreshes all use the same idempotent reducers.

Reaction and read facts are event/snapshot-authoritative.  A successful write
receipt settles its operation but does not invent a reaction count, membership,
or read frontier that Slack has not supplied.  Pending operation keys include
the exact account, conversation, message, and reaction/read identity.

* Update path

External domain work follows an explicit ownership path:

#+begin_example
HTTP result / realtime Source event
  -> normalize and validate exact owner
  -> commit canonical account facts
  -> closed command carrying a Surface change batch
  -> Surface update adjusts its own controller
  -> explicit projection request
  -> Generated Renderer reconciles stable rows
#+end_example

Finite acquisition Effects and live Sources return actual cancellation
capabilities.  Their mappers receive the captured input before result payloads.
Updates return closed commands rather than posting or sending reentrantly.
Transport callbacks never edit generated content or call row printers.

A live create can seed an authoritative-empty history window; a delete repairs
its exact edge before reconciliation.  User, conversation, reply, reaction, and
read changes retain stable row identity.  Presentation-only Resource completion
uses the Resource companion and dependent row interests rather than a domain
notification Effect.  Room and thread renderers redraw retained dependent rows
without reprojecting protocol messages or replacing their Resource interests.

* Appkit surfaces

** Root

=slackit-root-mode= derives from =appkit-directory-mode=.  It projects joined
conversations into three sections: direct messages, group direct messages, and
channels.  Entry keys are conversation IDs; activation opens the exact account
room.  User and conversation changes invalidate dependent entries without
rebuilding unrelated rows.

Bootstrap consumes every =conversations.list= cursor before declaring the
account directory ready.  It never scans the workspace-wide =users.list=
collection: visible direct messages, message senders, and =<@USER>= references
request exact =users.info= records through account-owned, deduplicated
operations.  Until a lookup settles, renderers expose the opaque user ID rather
than blocking startup.  Realtime =user_change=/=team_join= and joined-
conversation join/leave/rename/archive events keep existing rows and sender
dependencies current.

Canonical user records are an in-memory account cache, matching
=emacs-slack='s team-local user table; Slackit does not persist a second stale
directory of workspace profile metadata.  Public profile image bytes are the
expensive reusable part, so =slackit-avatar.el= caches them on disk under
account-qualified SHA-256 identities.  The cache directory is private on Unix,
downloads carry no Slack bearer or Cookie credentials, and Appkit derives
center-cropped circular images at the current two-line pixel size.  View rows
depend on opaque avatar resource keys for exact redraw after acquisition.

The root does not call =client.userBoot= or =client.counts= and does not invent
unread or mention badges.  It may mark a row unread only after the selected
transport supplies an authoritative read projection.

** Room

=slackit-room-mode= derives from =appkit-chatbuf-mode= and installs an Appkit
chat timeline.  It uses:

- =appkit-chat-timeline-project= and =appkit-chat-timeline-sync= for =ts=-keyed
  rows;
- =appkit-chat-history= for exact visible edges, loading ownership, older
  exhaustion, and passive delimiters;
- the Appkit chatbuf composer for the writable tail, draft history, reply/edit
  auxiliary state, and structured mention/channel objects;
- =appkit-chat-completion= for account-local =@user= and =#channel=
  candidates;
- resource dependencies for senders, user/channel references, account-local
  avatars, media previews/content, and custom emoji, with exact row invalidation
  after lazy resource or transfer-state arrival.

Slackit owns the row payload, Slack mrkdwn/reference interpretation, subtype
handling, clock text, sender selection, and actions.  It decodes entities once
and renders user, channel, special mention, date, safe link, code, and standard
Slack =:emoji:= tokens from stable protocol identities.  Message bodies and
actionable reaction chips share the same display resolver while canonical text
and reaction names remain unchanged for copy and wire operations.

Inline code is fixed-pitch.  A message containing canonical
=rich_text_preformatted= elements renders its ordered Block Kit source directly:
rich-text sections retain block order and each preformatted element preserves
its exact multiline text and explicit language.  Top-level =text= is not
rendered over that canonical structure; it remains a transport/accessibility
fallback.  Older fenced fallback text continues through exact ordered
descriptor matching.

=slackit-code.el= resolves a protocol language through the public
=org-src-get-lang-mode-if-bound= API, so installed modes and Emacs major-mode
remapping remain authoritative.  It never infers a language from code content
or conversation names; missing and unsupported languages stay fixed-pitch.
Fontification runs in hook-suppressed Slackit-owned scratch buffers, copies
only face properties, and uses bounded caches retired with the owning account.
Canonical message text, Block Kit payloads, and copied text remain unchanged.

Room and thread rows use the shared Appkit chat presentation primitives also
used by QQ and Disco: deterministic identity-colored sender headings,
center-cropped two-line circular avatars with initials fallbacks, responsive
right-aligned timestamps, full-width date/unread separators, wrapped body
prefixes, actionable reaction chips, and bounded same-sender compaction.  These
are display properties; copied message text remains free of alignment padding
and avatar placeholders.

=RET= is semantic activation, not a thread shortcut.  Inline action spans own
the exact sender/avatar, user/channel reference, link, media, reaction, or
reply-count behavior under point.  A plain message body does not infer a
thread.  =T= and the actionable =[N replies]= span open the exact thread.
The same action spans own mouse activation.  Their text-property keymaps take
precedence over the timeline fallback and remain isolated from the writable
composer.

Both chat Surface kinds enable =appkit-surface-enable-responsive-geometry=
after attachment.  Its owned callback updates the measured width and requests
a geometry redraw of the exact timeline keys.  Rendering a hidden buffer can
use =fill-column= temporarily; displaying or resizing it replaces that fallback
through the Surface-owned geometry lifecycle.

Unsupported blocks and subtypes remain visible as explicit safe rows.  Slack
file objects project typed photo, video, audio, or document cards.  Preview
resources remain separate from original content resources: images and video
posters render from bounded caches, while open/play/download/save actions use
validated local content files.  Public Block Kit media is credential-free.
Private Slack content is accepted only from exact HTTPS =files.slack.com=
=files-pri=/=files-tmb= paths and uses only its owning account's =xoxc= bearer
plus =d= cookie, with redirects disabled.  Login HTML, empty content, stale
generation callbacks, and partial files are rejected; Unix cache directories
and completed files use modes =0700= and =0600=.  Media card contexts and
resource keys contain only opaque account-qualified hashes, never URLs or
credentials.  Photos/GIFs open through Appkit's local image runtime.  Videos
play from local files through the initiating Surface's lifecycle-owned player.
Audio downloads before a real Surface Source starts playback.  Progress and
finalization use Source output; repeat activation uses a closed outbound toggle
intent, and Source cancellation stops the exact player.
Documents download before the configured local file opener.  Appkit card
actions expose open/play, download, cancel, and save-as;
media actions never fall back to a browser.

Avatar, preview, and custom-emoji image acquisition is declarative.  The
Generated Renderer returns deduplicated demands for the projected history
window and the exact row interests that depend on each resource.  Loaders own
cache discovery, private-directory preparation, transport, validation, and
cancellation; row projection starts no acquisition.  Logical entries use
=while-interested= retention while validated bytes remain separately cached on
disk.  Explicit open/download/save commands start initiating-Surface acquisition
Effects; committed successful acquisition starts local presentation, or declares
the audio playback Source.  A retired Surface cannot present a late download.

Initial room history uses =conversations.history=.  The room owns its returned
older cursor because Appkit deliberately does not interpret protocol cursors.

- An empty first response calls
  =appkit-chat-history-window-establish-empty=.
- A non-empty latest response sets the exact first key and a nil last key,
  meaning attached to the live frontier.
- The response cursor is used for the next older page.
- An absent next cursor marks the older edge authoritative.
- Realtime creates extend an attached-latest window without guessing across a
  partial window.
- Exact slicing happens before subtype visibility filtering, so a hidden reply
  cannot manufacture a false history gap.

** Thread

=slackit-thread-mode= is a separate Appkit chatbuf/timeline view keyed by
=(thread CONVERSATION-ID ROOT-TS)=.  It loads root/replies through
=conversations.replies=, whose cursor advances toward newer replies rather than
older room history.  While that cursor remains, the Appkit window has an exact
newer edge; exhaustion attaches it to latest.  Replies are sent through
=chat.postMessage= with =thread_ts=.  Slackit does not use
=subscriptions.thread.*= or =client.counts=.

The canonical message exists once per conversation; room and thread projections
select different indexes.  Reply create/change/delete events update the open
thread and its parent row metadata.  =thread_broadcast= reconciles into both
views without duplicating either row.  Closing the thread does not cancel an
already dispatched reply.

** User profile

=slackit-user-mode= is an Appkit view keyed by =(user USER-ID)=.  It renders
only canonical account user state: circular avatar, display/real names,
username, Slack status, title, pronouns, timezone, custom profile fields,
authorized contact fields, role badges, and deactivation/bot state.  Opening a
cached user renders immediately and starts one view-owned =users.info= refresh.
The returned user ID must equal the requested opaque ID.  A killed/replaced
view retires its operation and HTTP owner before a delayed callback can update
state.

Sender headings, avatar slices, and exact =<@USER-ID>= references use Appkit
action spans to open the corresponding account-owned profile.  Pure =bot_id=
identities are not projected as Slack users.  =user_change= events update the
canonical user and invalidate only the matching profile plus dependent chat
resources.

The Message action first reuses a canonical live =is_im= conversation for the
user.  Otherwise it sends one non-retried, view-owned =conversations.open=
write, validates the returned channel/user identity, upserts the IM, and opens
the ordinary =(room CONVERSATION-ID)= view.  Concurrent activation is
deduplicated; stale view/account callbacks neither publish a conversation nor
jump buffers.  User buttons, Evil bindings, and the user Transient all retain
the same exact view scope.

** Composer and completion

The composer serializes ordinary text plus structured =@user= and =#channel=
objects to exact Slack ID forms.  Candidate labels are account-local and
collision-safe; display text is never the wire identity.  =C-c C-a= is a
Telega-style attachment-action dispatcher rather than an immediate file
prompt.  Its ordered, customizable actions expose only distinct Slack or local
acquisition semantics: an editable fenced code block, an uploaded code
snippet, unified media/file selection, an image carrying =alt_txt=, and a
clipboard image when graphical clipboard data is available.  =C-c C-f= is the
direct media/file shortcut.

Local files use the same Appkit atomic input-object boundary as Telega-style
attachments: the safe name/type/size label is composer presentation, while the
local path remains Slackit-owned object data and never becomes message text.
A code-block action first selects an explicit editing language, resolves its
native Emacs mode through Org plus =major-mode-remap-alist=, and opens
=appkit-compose-edit-buffer= under the exact room/thread view.  Appkit owns the
temporary recursive editor, finish/cancel keys, native-mode keymap layering,
buffer cleanup, and owner shutdown.  Slackit validates the returned code and
atomically inserts or replaces a structured code-block object.  Composer
presentation is deliberately one line—language plus line/character counts—so
multiline source never violates Appkit's cursor-intangible object geometry.
Cancellation does not mutate the composer.

Slack mrkdwn fences cannot declare a language.  A code-rich room send, thread
reply, or edit therefore carries two coordinated representations:

- top-level =text= is an escaped fenced fallback for notifications,
  accessibility, and clients that ignore blocks;
- =blocks= preserves ordered non-code spans as =section/mrkdwn= and compiles
  each code object to
  =rich_text/rich_text_preformatted(language=LANGUAGE)=.

The explicit language is therefore both local native-mode metadata and Slack
syntax-highlighting metadata.  Code blocks require it.  Slack file completion
accepts only =initial_comment= rather than arbitrary blocks, so one submission
cannot mix language-declared code objects with uploaded files; Slackit rejects
that combination instead of silently dropping the language.

Code snippets carry the explicit optional =snippet_type= through upload
negotiation and enforce Slack's documented 1 MiB limit.  Clipboard bytes are
frozen in a private =0700= temporary directory with a =0600= file; a view-owned
Appkit handle removes it when the attachment is deleted, its successful
unchanged draft settles, or the view stops.  Cancellation retains that draft
and temporary file.

The same composer auxiliary state supports a plain room send, a thread reply,
and editing one owned message.  File attachments are accepted for room sends
and thread replies, not message edits.  Slackit does not implement general rich
WYSIWYG or arbitrary Block Kit authoring; the code-block compiler is one narrow
typed transport.

Text writes freeze their semantic input and Appkit composer revision while the
account-owned request is in flight.  File sends additionally use one
=appkit-compose= operation for generation fencing, status/progress rendering,
and cancellation.  Slackit then runs the protocol-owned sequence
=files.getUploadURLExternal= → credential-free multipart capability upload →
=files.completeUploadExternal=.  Capability URLs must be exact HTTPS
=files.slack.com/upload/v1/= values; the streaming curl process receives no
bearer or cookie, never redirects or retries, and keeps the URL/path out of its
argv.  Several files upload in order and complete as one channel/thread share
with the captured text as =initial_comment=.  Cancellation retains the atomic
draft.  A completion failure is treated as an unknown remote outcome and is
never replayed automatically.

Success clears or exits the operation only if that same chatbuf revision is
still current; failure leaves the draft editable and displays a redacted Slack
error.

The HTTP response and matching realtime event may arrive in either order.  Send
and edit converge through the server =(conversation-id . ts)= reducer; delete
converges through the same tombstone.  The first slice does not create an
optimistic timeline row or automatically retry a write with an unknown outcome.

** Reactions and read state

History/reply snapshots render reaction name, count, and current-user
membership as text.  =reactions.add= and =reactions.remove= are account-owned;
Realtime =reaction_added=/=reaction_removed= events are authoritative and
invalidate only the affected row in every projection.  One latest operation per
=(account, conversation, ts, reaction)= prevents a stale REST completion from
overwriting a later opposite action.

Room read advancement uses only the newest canonical row actually reached in
an exact visible window.  It never crosses an unknown history gap.  Mark writes
through =conversations.mark= are monotonic and coalesced per account and
conversation; =*_marked= events update canonical =last_read=.  A write receipt
settles pending work but does not fabricate unread counts or locally clear an
unknown server badge.

* First daily-use vertical slice

The first delivery is intentionally larger than a transport demonstration.  It
is complete only when one or more registered accounts can:

1. capture an existing Slack browser login through account-isolated
   =browser-session= profiles, import only =d=/=d-s=/=lc= plus the page token,
   persist private versioned auth, and delete the temporary capture;
2. start independently from stable local account IDs with account-local,
   origin-bound credentials and secret-free diagnostics;
3. consume every conversation cursor, seed self identity, resolve visible users
   once on demand, project readiness honestly, and honor bounded =Retry-After=
   only for idempotent reads;
4. reach realtime =hello= through the authenticated Web/Desktop gateway,
   maintain ping/pong, rebuild reconnects with a generation fence, and keep
   user/conversation metadata current;
5. open an Appkit directory root, exact account-owned conversation room, and user profile;
6. load the latest exact message window, page older with the returned cursor,
   and merge pages safely against later realtime edits/deletes;
7. render Slack references, safe links/code, standard/workspace emoji,
   reaction chips, circular avatars, typed media previews, local
   photo/video/audio/document actions, and explicit unsupported content;
8. complete =@user=, =#channel=, and Slack =:emoji:= names from exact account-local identities;
9. apply realtime top-level, nested change/delete, reply/broadcast, reaction,
   marked, user, and joined-conversation lifecycle events;
10. send room text or an ordered external-upload file share and reconcile
    HTTP/realtime arrival in either order without an optimistic row or
    automatic write retry;
11. open a stable thread view, load/page replies, receive reply mutations, and
    send a reply;
12. edit and delete an owned message with revision/tombstone-safe settlement;
13. render, add, and remove emoji reaction chips with REST/realtime race safety;
14. advance and explicitly mark read only through an authoritative reached row,
    without =client.counts= or fabricated unread badges;
15. activate sender/avatar/mention/media/reaction/reply-count semantics through
    exact =RET=/mouse action spans, with =T= reserved for explicit threads;
16. reuse or safely create an account-local direct-message room from a user profile;
17. stop with no live Slackit WebSocket, timer, request, operation, login
    capture, or view left behind; and
18. coexist with =slack= and expose optional Evil plus exact-scope Transient menus.

Deferred after this slice: remaining rich Block Kit attachments and WYSIWYG,
screenshot/recording acquisition, global search, notifications,
unread/modeline count summaries, typing, presence, DND, thread
subscription/activity endpoints, pins/saved items, scheduled messages,
workspace administration, OAuth/token refresh/Socket Mode, enterprise-token
selection, and optimistic local timeline rows.
Unsupported content remains visible without silently expanding a deferred
transport surface.

* Contract checks

Implementation should defend these observable contracts:

- loading =slack= and =slackit= together produces no feature, file, symbol,
  Custom group, face, mode, or buffer ownership collision;
- two accounts with equal conversation/message/root =ts= values never share
  state, requests, operations, completions, marks, or views;
- canary credentials never appear in identities, rendered buffers, errors, or
  diagnostics, and cross-origin/redirect/media URLs receive no Slack secrets;
- avatar resources reject non-HTTPS/non-Slack hosts, never receive Web API
  credentials, deduplicate account-owned transfers, persist only private image
  bytes, derive circular size/mtime-specific images, and redraw exact rows;
- media resources separate preview and content identities; exact private Slack
  hosts receive only the owning account's bearer/=d= credentials with no
  redirect; HTML login responses and partial files never become cache entries;
  photo/video/audio/document actions download before local open/play, expose
  cancel/save state through Appkit, and keep URLs out of row contexts, resource
  keys, rendered output, and diagnostics;
- capture callbacks and diagnostics contain no secret values; imported auth and
  temporary capture files are private; capture files are deleted on success,
  failure, cancellation, and synchronous startup errors;
- two accounts never share a browser profile root or auth path, and a later
  capture cannot silently replace an established different team/user identity;
- captures with a wrong source URL, non-Slack cookie domain, duplicate/missing
  cookie, unsafe cookie value, unsupported schema, or non-=xoxc= page token are
  rejected without persisting credentials;
- login capture requires the canonical HTTPS Slack customize origin, complete
  team/user identity, private storage, and one global browser-session owner;
  captured identity remains pinned through =auth.test=;
- two-page conversation fixtures do not become ready after page one; startup
  never calls =users.list=, and repeated visible references share one pending
  =users.info= operation;
- realtime readiness requires =hello=; only one reconnect attempt exists per
  live generation; stop/restart makes every prior callback inert;
- timestamp ordering remains correct for fixed-width decimal strings;
- a delayed room/reply history page cannot overwrite a later realtime edit or
  resurrect a delete;
- empty history followed by a live message becomes one attached-latest row;
- initial and older pages preserve exact Appkit edges and do not project cached
  islands across an unknown gap;
- user/conversation metadata events retain and narrowly invalidate unaffected
  root/timeline rows;
- ordinary replies stay out of the top-level sequence, while broadcasts appear
  once in both the room and thread;
- completion serializes the selected account's exact user/conversation ID even
  when labels collide or later change;
- standard colon emoji resolve only at presentation, unknown names remain
  literal, reaction chips preserve exact Slack names, and adjacent identical
  structured mentions serialize as separate occurrences;
- public media resources contain no raw source URL or credential, start outside
  rendering, and settle loading to preview/failure by exact row;
- Evil remains optional, with deliberate modal message actions and the
  timeline/composer boundary; Transient suffixes retain their original live
  Appkit view/account/message generation;
- send/edit HTTP snapshots cannot overwrite a later realtime edit or clear a
  tombstone; response-before-event and event-before-response orders converge to
  one server row;
- editing text or structured objects during an in-flight write prevents stale
  success/failure from overwriting the newer composer;
- reaction event-before-REST and REST-before-event update once; reversed
  add/remove completions leave the later action authoritative;
- read marks advance monotonically only to a reached row and never cross an
  unknown gap; receipts do not fabricate read/count state;
- no write is automatically retried after timeout, rate limit, or unknown
  outcome; and
- external domain results commit canonical/controller state and explicit
  projection requests; only Generated Renderers mutate generated content,
  preserving point, window start, draft text, and undo history.
